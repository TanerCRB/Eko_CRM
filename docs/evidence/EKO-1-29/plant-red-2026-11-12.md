## Mechanisms landed (C-1/C-2)

- Raw branch: `RAW_CANDIDATES = (?=( <raw pattern> ))` enumerated with `finditer` — a zero-width
  wrapper advances one position at a time, so no candidate can hide behind an earlier one. A
  restart at `match.start()+1` would NOT have fixed it: the swallowing assignment's own match
  starts at index 0 (its slot prefix begins before the hidden candidate), so any restart past 0
  excludes it — recorded because the naive fix looks correct and is not.
- Diff branch: split into `DIFF_LINE_MARKER` (`+` at line start or directly after
  `    \v \f \x85`, with `(?!\+)` keeping `++`/`+++` headers out) and a context-free
  `ASSIGNMENT_TAIL` enumerated after the marker. The old anchored mid-line form could not
  re-scan for later candidates at all (every match starts at index 0), so the enumeration had
  to move into the tail.
- Slot context: `[A-Za-z_]...=(?:"…"|'…'|bare),?[ \t]+` — quoted first values and
  comma-terminated slots now open the assignment context. The dev-2 rationale "the second-slot
  context excludes `\"`, `'`, `,` from the preceding value so Python call sites cannot match"
  is SUPERSEDED as the reason: Python call sites keep holding because no `NAME=` is adjacent to
  their arguments (`url, client_secret=...` carries no `=`-terminated name before the target),
  not because quotes and commas are excluded. Behavior at the tree is identical (census below).
- Boundary landed on the quoted-first-slot / Python-call-site question (reviewer R-05, C-1):
  `self._post(url, client_secret="hunter2")` HOLDS by design — repo style is one kwarg per line
  (ruff magic trailing comma) and `    client_secret="hunter2",` on its own line FIRES; both
  directions are committed (`test_eko129_c1_*`). An UNTERMINATED quoted slot value
  (`FOO="a b TOKEN=x`) opens no context — the slot grammar needs a closed quote or a bare
  token; the target's own unbalanced quote stays a literal (dev-2 G-01, unchanged).
- Attached flags (C-4 recommendation taken up): `--env=TOKEN=x`, `-e=CLIENT_SECRET=x`,
  `-eCLIENT_SECRET=x`, `env=TOKEN=x` fire. `[ "$rc" -eq 2 ]`-style flags do not match: after
  the attached `-e` alternative the name must be keyword-terminated immediately before `=`,
  and census: no such line on the tree. `--env-file` is safe (`-` is not in the letter
  lookahead).
